# Historical Claim Policy

**Date:** 2026-09-24

Historical claims are the easiest place to accidentally turn a proposal into a false history. Every public statement must be classified as one of the following.

## Claim levels

### Level 0: Observation

A direct, reproducible observation with a source.

Example: “The itch.io page for *#21: The World* says it is based on the creator's own dream journal.”

### Level 1: Documented project fact

A local file, commit, official page, or attributable interview supports the statement.

Example: “The project repository contains a C++ Dream Director and a procedural childhood-bedroom builder.”

### Level 2: Research conclusion

A synthesis of multiple sources, with uncertainty and contradictions stated.

Example: “The available evidence supports treating Dreamcore as a working category rather than an established formal genre.”

### Level 3: Historical priority claim

A claim that something was first, invented, originated, or preceded another work.

Priority claims require a defined search boundary, dated sources, and a clear comparison set. This project currently has no Level 3 evidence for inventing Dreamcore or for creating the first Dreamcore Horror game.

### Level 4: Promotional claim

A sentence intended to persuade rather than document. It may contain Level 0–2 facts but must not exceed their evidence.

## Approved wording patterns

- “The available research found…”
- “The project proposes…”
- “The creator reports…”
- “This is the earliest example located in this pass, not necessarily the first historically.”
- “This game is a candidate under the proposed definition.”
- “The term is also used for…”
- “No independent adoption was verified in this research window.”

## Words requiring special care

| Word | Why | Preferred alternative |
|---|---|---|
| first | Requires priority evidence | earliest located / first documented in this pass |
| invented / coined | Requires a documented coinage event and comparison | proposed / working term |
| established | Requires repeated independent use and shared criteria | emerging proposal / working category |
| inspired by | Can mean influence, not provenance | “The creator states the work is based on…” |
| based on | Can be used loosely | specify the source and materiality |
| official | Can imply endorsement | “the project's own documentation says…” |
| community | Vague | name the platform, tag, forum, or survey |
| popular | Requires data and method | report the observed count and date |
| legal | High-risk | “requires professional review” |

## Archive rule

A claim should be promoted from research to public copy only when:

1. a source ID exists;
2. the source URL/path and access date are recorded;
3. the source's wording is preserved accurately;
4. any inference is labelled;
5. contradictory evidence is noted;
6. privacy and consent are checked;
7. the claim remains true if the source changes.

## Priority review procedure

If a future “first” claim is proposed:

1. Define what counts as the category (base or horror branch).
2. Define the medium (game, interactive work, public release, jam, prototype).
3. Define the time and geographic boundaries.
4. Search primary archives and creator records.
5. Record every plausible earlier candidate.
6. State “earliest located” if priority cannot be established.
7. Obtain legal review for any “first”/“invented” wording used commercially.
